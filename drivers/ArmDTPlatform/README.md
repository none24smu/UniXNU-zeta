# ArmDTPlatform: explicit platform identity

This experimental board-local driver overlays the standard `ArmDTPlatform`
module. It is copied from UniXNU/ArmDTPlatform commit
`0d544705c2e89725caabc0542bb96bc8febd8c70`; `UPSTREAM.json` records that source.
The current control's driver and root repository are unchanged.

`getModelName` and `getTargetName` read the provider's `target-sub-type`, falling
back to `target-type` if the former is absent. If both are absent, they preserve
inherited compatible-based naming. A present but malformed property returns
failure rather than silently selecting another identity. Strings must be
nonempty, terminated, and fit the caller's buffer. Zero padding is accepted;
multiple strings are rejected. A null provider/output or capacity below two
returns failure. The driver does not change any device-tree property.

For the experimental ADT this means expected `hw.model` and `hw.target` are
`V68AP`; root `target-type` remains `V68`. Inherited machine/product naming still
uses root `model`, which is `iPhone19,4`. Root `compatible` and the CPU, GIC,
Qualcomm bus/device descriptions remain the real Surface Duo 2 hardware values.
These are expected outputs, not observed runtime sysctls.

## Build wiring

No additional feed override or build-script hook is required. The existing
`unixnu.feeds.resolve` prefers `board/drivers/ArmDTPlatform` over the root
repository's driver. `unixnu.tree.assemble` links that module into
`tree/drivers/ArmDTPlatform`. The existing `build-xnu-12377.sh` invokes
`build-platform-12377.py ArmDTPlatform`, which compiles this source using the
saved `IOPlatformExpert.cpo.json` recipe and links `libArmDTPlatform.a` into XNU.
`CONFIG_XNU_ARM_DT_PLATFORM=y` is already present in this board's defconfigs.
The host check exercises the real resolver and verifies device-module selection.

## Validation

Run from the workspace:

```
python3 work/ios27-port/board/scripts/check-armdt-platform-identity.py \
  --unixnu-root UniXNU --xnu-source work/xnu-12377 \
  --output work/ios27-port/identity/host-check
python3 -m unittest discover -s work/ios27-port/board/scripts/tests \
  -p test_zeta_ios27_profiles.py
```

The host check compiles the actual production identity method bodies with a
narrow IOKit adapter and executes them under address/undefined-behavior
sanitizers. It covers explicit precedence, absent/invalid properties, empty and
unterminated data, multiple strings, padding, exact/short/invalid buffers,
virtual dispatch, inherited fallback, read-only properties, and the exact ADT
generated by the board's payload entrypoint. It checks the virtual method
signatures against the inspected XNU header.

This is not a native kernel SDK/ABI compile. The full driver must next compile
on the existing macOS XNU build path, and a later recovered-device test must
read the actual sysctls. No boot image was built or deployed for this change.
The iOS 27 `arm64e.x1` executable/cache conversion gate remains closed: identity
coherence does not provide ADDPT/SUBPT, CSSC, MTE, POE2, or remaining system/kernel
compatibility. See the board's existing x1 audit artifacts for exact counts.
