# Experimental iOS 27 x1 CPU and loader conversion

The iPhone19,4 / 24A94425 launchd, dyld and SystemOS cache require more than stripping pointer authentication. Their original code includes FEAT_PAuth_LR, pointer arithmetic from CPA/CPA2 and scalar CSSC instructions. The default converters still reject arm64e.x1. A separate `sm8350-x1-experimental-v1` profile can plan exact edits, but cannot emit executables with a draft kernel contract.

## Read-only plans

`rewrite-zeta-userland.py --plan-only --input IMAGE --apple-trust-cache ORIGINAL_TRUSTCACHE --report PLAN.json` verifies the original signature and Apple trust-cache membership, proves code, and records PAuth/PAuthLR plus CPTA-OFF ADDPT/SUBPT/MADDPT edits. It emits no executable or new trusted CDHash. Plan-only pointer lowering is a proposed compatibility policy, not proof that the running guest has that policy.

`prove-zeta-dyld-cache.py --experimental-x1-plan --cache CACHE --work OUTPUT --jobs 2` validates subcache UUIDs, mappings, slide-v5 geometry and code boundaries, then records an edit plan and remaining ISA requirements. `--only` makes a bounded diagnostic proof; it cannot qualify a cache rewrite. Original file and proof-tool hashes, per-image edit-array hashes and unresolved candidates are retained.

The x1 code proof recognizes exact TCHANGE instruction forms as fallthrough code without modifying their semantics. Detached executable selector thunks require the complete ADRP-X1 / ADD-X1 / B-to-owned-code / BRK pattern and an incoming proven branch. The pattern does not turn arbitrary cache mapping gaps into code. A call can terminate a path only through exact exported noreturn APIs (assert, stack-check failure, abort, exit or C++ terminate) and their exact executable forwarding thunks, or a locally proven trap body. The local rule requires an unwind-covered function start with a PAC prologue, at most32 decoded straight-line words and an exact BRK#1, without atom crossings, branches, returns or missing/data words. Arbitrary terminal calls remain rejected.

## Executable conversion gate

`--x1-contract` must identify a validated `zeta-x1-kernel-contract-v1` manifest. `zeta_x1_compat.load_contract` checks immutable kernel, source, helper and adapter artifacts; effective guest observations; and native EL0 evidence. Required policy includes ordinary-pointer ABI, disabled/unadvertised GCS, no advertised PAuth/CPA2/MTE, explicit effective CPTA OFF, platform-task scoped opt-in CSSC support for all seven supported scalar operations, and a verified disabled hardware-TPRO path. CPTA OFF is a chosen compatibility policy: it does not retain Apple's CPTA-ON poison checks.

Platform-task CSSC qualification must use a signed probe with a basename distinct from `zeta-isa-probe`. The manifest verifies the probe's actual primary CodeDirectory CDHash and requires successful self `CS_OPS_STATUS`/`CS_OPS_CDHASH` return codes, the platform bit and CDHash, exact kernel identity, a mode1 negative result and mode2 positive result for the same probe. Static trust-cache membership alone does not prove the process is platform signed; AMFI's signature-policy callback supplies that status. A mode1 probe-only pass cannot qualify launchd.

Retained TPRO, MTE, SHA512, RCPC2 and AMX words require either native execution evidence or exact-input-bound disabled-path evidence. They are not replaced with NOPs. Unknown instructions, code-boundary anomalies, unlowerable pointer forms and unproven candidates stop conversion. Cache rewriting additionally requires the complete image set and matching original/proof/tool hashes. The cache family retains its UUIDs, layout, slide chains and original-to-owner trust attributes; declared architecture headers and code signatures are updated only after qualification.

## Current limit

The working contract remains draft. No iOS 27 converted executable or cache has been issued by this profile, and no iOS 27 runtime success is claimed. Local read-only plans and diagnostics are under `../x1-conversion/` outside the board repository.

The CSSC trap helper is a compatibility fallback, not a 60/90 Hz performance result. A hot CTZ can need RBIT+CLZ with a relocated second instruction; general min/max needs comparison/selection and often flags preservation. Future AOT sequences therefore require relocation, register-liveness and NZCV proofs. Some exact special cases can fit one word (for example UMIN-immediate0 to MOVZ, UMAX-immediate0 to MOV), and the experimental planner now records exact single-word cases; executable output still requires the full validated contract. Instruction-site counts do not measure runtime trap frequency or frame time.

## Native scalar compatibility checkpoint

The retained iOS26 diagnostic kernel `ec2a39c3800afe118f8de964223808a764573f5597f2929949422d88e1c6030d` passed five physical phases: disabled, exact probe basename enabled, distinct platform basename denied in mode1, that same signed platform process enabled in mode2, and disabled again. Both enabled phases passed32 instruction forms across9 edge values each, then10000 timed CTZ calls. Each enabled phase added exactly10288 emulations. All disabled/denied phases trapped32 forms with zero emulations; the final diagnostic mode was0. Successful selfcsops status/CDHash calls bind the distinct process to the exact signed probe; owner trust alone was not used as proof.

`normalize-zeta-native-cpu.py --directory EXPERIMENT --output NEW.json` checks all five original phase captures against fixture words, semantic edge counts, mode/gate state, counter deltas, actual signing identity and negative controls. It separately checks later corroborating128-byte kernel windows and full probe/launcher/alias byte readbacks. Those later bytes are explicitly dated after the phases; they are not presented as original phase bytes. Retained paths are under `../isa-compat/normalized-native-cpu2/`; source snapshots, CI ZIPs and the final guarded/prelinked kernel are hashed separately.

The10000-CTZ runs took6450625ns in exact-probe mode and18791198ns in platform mode, versus25885ns and139688ns for RBIT/CLZ baselines. These uncontrolled samples include wrapper and load costs; they establish neither steady trap latency nor UI frame rate. They support avoiding pervasive traps as the final performance strategy.

Actual probes also trapped LDAPUR, six FJCVTZS operands, SHA512, IRG, pointer arithmetic and PAuth/PAuthLR. The guest reported JSCVT/LRCPC2/MTE/SHA512/PAuth/CSSC disabled, SME/SME2 zero, and commpage bit60 clear. GCS/CPA/CPA2 sysctl names returned ENOENT. These observations must retain their exact meanings: missing nodes do not establish architectural absence or disabled control state. The contract remains DRAFT pending GCS qualification, ordinary-pointer ABI policy, retained feature paths, code boundaries and actual iOS27 loader/process execution. No iOS27 executable was emitted by this test.

## Exact baseline translations under development

The single-word CSSC path handles only exact MOV/MOVZ/MOVN equivalents: degenerate equal-register min/max, unsigned zero operands, selected zero immediates and constant ZR cases. Both image/cache planners and the cache edit verifier use the same bounded selector. QEMU executed6306 accepted baseline encodings across201792 operand/flags cases against the independently checked C helper, preserving W zero-extension, ZR behavior and NZCV. No NOP or scratch register is used. The original cache contains only25 such raw section candidates (24UMAX,1UMIN), so this is a limited improvement rather than the bulk performance answer. The census itself does not prove code reachability.

General CTZ has184328 raw section candidates and needs RBIT then CLZ. `zeta_x1_thunks.plan_ctz` now plans an exact branch/RBIT/CLZ/return sequence with signed imm26 range checks and stage-specific PC metadata. It reserves no arena, writes no executable and selects no conversion. A signal after RBIT can see an intermediate destination; translating its PC alone is insufficient. Async completion, debug/fault/unwind behavior and signed arena integration remain required before using these thunks in an OS image. LLVM verified4096 exact RBIT/CLZ encodings across all32 source/destination registers and both widths; QEMU executed18 actual branch/RBIT/CLZ/branch thunks over2304 operand/flags cases. Those tests establish baseline arithmetic and branch behavior, not signal/unwind qualification. The native scalar trap fallback remains the functional option in the meantime.

The original dyld SHA512 selector is also traced in `../x1-conversion/dyld-feature-dispatch/sha512-dispatch.json`: all144 unsupported SHA512 sites lie in one hardware helper, while `_ccsha384_di` reads the observed commpage value and selects the baseline NEON/scalar digest table. Exact selector/table/wrapper bytes are retained. The incoming direct branch and bounded pointer/address-pair scans agree with that path; they do not yet close arbitrary computed indirect targets, so the complete retained-feature contract remains unqualified.

The complete frozen-v2 cache proof now covers4702 images (4572 code,130 empty) and68 islands. Independent verification checked78 input hashes,5 tool hashes,4640 result-array hashes and49125328 original planned words against source bytes. It reduced unproven candidates11820→1924, undecodable leaves2405→278 and section exits471→266. The remaining boundaries/features still stop conversion. The frozen proof predates later AOT aliases and must retain its own matching tools. See `../x1-conversion/cache-proof-full-lr-register/independent-validation.json`.

The selected libc++abi follow-up resolves its sole section-exit anomaly: the final BL at0x2be0968f4 targets the exact original `___cxa_throw` export. The experimental fatal API set now includes the ABI's `___cxa_throw`/`___cxa_rethrow` noreturn contracts; exception landing pads remain independent roots. Reproving this image produced zero anomalies/unproven words and exactly the same1365 original/replacement word pairs. This selected pass is not a replacement for the full cache proof.
